# Release v3.7.7

## Overview
This release fixes a critical bug in error reporting for edge cases and improves documentation with new getting-started examples.

## 🐛 Bug Fix: Issue #596 - Empty Input Error Handling

**Problem:** 
Parser crashed with `IndexOutOfRangeException` when:
- Processing empty input
- Line number in error exceeded the actual line count
- This commonly occurred when parsing fails at end-of-stream (EOS)

**Root Cause:**
In `ParseError.cs`, the error message formatting directly accessed `fullSource.GetLines()[line]` without bounds checking.

**Solution:**
Added bounds validation before accessing line content:

```csharp
// Before: Direct access could throw
var theLine = fullSource.GetLines()[line];

// After: Safe access with bounds check
var allLines = fullSource.GetLines();
if (line < allLines.Count)
{
    var theLine = allLines[line];
    // Build error message with line context
}
```

**Files Changed:**
- `src/sly/parser/parser/ParseError.cs`

## 🎓 Documentation Improvements

### New Getting Started Examples
Added comprehensive examples for users new to CSLY:

**Files Added:**
- `src/samples/ParserExample/GettingStarted.cs` - Basic usage example
- `tests/ParserTests/Issue596/Issue596Parser.cs` - Parser implementation
- `tests/ParserTests/Issue596/TestIssue596.cs` - Complete test suite

**Example:**
```csharp
// Simple expression parser: 1+2+3 = 6
var parserInstance = new GettingStartedParser();
var builder = new ParserBuilder<GettingStartedLexer, int>();
var buildResult = builder.BuildParser(parserInstance, 
    ParserType.LL_RECURSIVE_DESCENT, "expression");

var parser = buildResult.Result;
var result = parser.Parse("1+2+3");
Assert.Equal(6, result.Result);

// Also handles errors gracefully
result = parser.Parse("");
Assert.True(result.IsError); // No exception, proper error reporting
```
